# System overview

The pnpm workspace separates the web application, shared schemas, future SDK, datasets, database migrations and Python validation. Next.js App Router serves the public pages and API routes. Tailwind's build integration and shared CSS provide responsive styling. Lucide supplies interface icons.

The configured default interface uses a shared Supabase workspace. `/api/workspace` returns published rows plus only the revisions/comments/disputes visible to the verified user under RLS. Client mutations call validated server endpoints; user/profile identities and editorial roles are read from Supabase, not local storage. Profile setup and the original dataset workflow are connected. The separate `/demo/` interface retains the browser-local Workspace with synthetic entries, immutable history snapshots and dispute evidence. Demo transition rules are unit-tested but protect no real data.

Authenticated server API routes use Supabase SSR cookies, `auth.getUser()`, Zod validation and an ordinary publishable-key client. Next Proxy refreshes sessions with verified claims; API authorization remains independent of Proxy. PostgreSQL RLS and security-definer functions are the final authority. Mutations check the exact configured/request origin, including safe normalization of local loopback hosts. No service-role credential bypasses RLS. PKCE and supported email token-hash callbacks return to the canonical origin. Email-code verification and local sign-out have dedicated endpoints.

Published dataset rows are append-only to client roles. Proposal revisions hold editable draft content; audit snapshots preserve earlier content. Publication inserts a new accepted row, preserving previous published versions. Review decisions and dispute evidence remain separate immutable records. Public exports select only the accepted table and redistributable licenses.

The community domain module adds synthetic profiles, scholar applications, independent role grants, review assignments, discussions, article revision/publication and immutable release snapshots. Changes record actor, rationale, timestamp and content snapshots. Schema-validated restoration preserves old demo saves and retains an invalid save in a recovery key. Storage events synchronize open tabs; this is a last-write-wins demo, not a concurrent shared database.

The locale context translates interface copy and stores the English/Somali preference. Submitted language content is displayed verbatim as React text, never interpreted as HTML. Keyboard dialogs trap focus, close on Escape and mark background content inert. Global headers deny framing, MIME sniffing, embedded objects and unnecessary device permissions.

Supabase integration has resumed with applied migrations and actual anonymous dataset reads. Shared role/scholar/article/release administration, review assignment/evidence/history presentation, pagination, notifications and concurrent-user tests are still pending. Unsupported live workflows display an explicit unavailable state; they never silently become local demos. Database responses are refreshed after writes and when the tab regains focus, without optimistic publication or local persistence of private data. Real email/cookie-refresh tests require user-assisted sign-in. Do not connect the demo role selector to real authorization.
