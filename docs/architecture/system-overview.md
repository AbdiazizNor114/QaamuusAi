# System overview

The pnpm workspace separates the web application, shared schemas, future SDK, datasets, database migrations and Python validation. Next.js App Router serves the public pages and API routes. Tailwind's build integration and shared CSS provide responsive styling. Lucide supplies interface icons.

The application uses a public catalog and a shared Supabase workspace. `/api/workspace` returns published rows plus only the revisions/comments/disputes visible to the verified user under RLS. Client mutations call validated server endpoints; user/profile identities and editorial roles are read from Supabase, not local storage. Missing configuration displays an unavailable state, not synthetic content or a local role selector. Removed sandbox URLs return 404.

Authenticated server API routes use Supabase SSR cookies, `auth.getUser()`, Zod validation and an ordinary publishable-key client. Next Proxy refreshes sessions with verified claims; API authorization remains independent of Proxy. PostgreSQL RLS and security-definer functions are the final authority. Mutations check the exact configured/request origin, including safe normalization of local loopback hosts. No service-role credential bypasses RLS. PKCE and supported email token-hash callbacks return to the canonical origin. Email-code verification and local sign-out have dedicated endpoints.

Published dataset rows are append-only to client roles. Proposal revisions hold editable draft content; audit snapshots preserve earlier content. Publication inserts a new accepted row, preserving previous published versions. Review decisions and dispute evidence remain separate immutable records. Public exports select only the accepted table and redistributable licenses.

Shared community workflows cover profiles, scholar applications, independent role grants, review assignments, discussions, article revision/publication and immutable release snapshots. Changes record actor, rationale, timestamp and content snapshots in the database. No browser-local role identities or simulated decisions are shipped.

The locale context translates interface copy and stores the English/Somali preference. Submitted language content is displayed verbatim as React text, never interpreted as HTML. Global headers deny framing, MIME sniffing, embedded objects and unnecessary device permissions.

The third migration and shared community API connect scholar decisions, controlled role administration, private article review/publication/corrections and frozen releases. Community commands are a schema-validated RPC allowlist; PostgreSQL derives actors from auth.uid(). Role decisions serialize under an advisory transaction lock, reject self-changes and audit rationale. Article transitions lock the proposal row and never overwrite published content. Release creation freezes server-selected published rows and manifests; download endpoints read the stored snapshot, not client content. The member directory reveals only names/IDs/roles to editors and operational admins. Private scholar/article/audit reads remain RLS-filtered. No founding roles are seeded.

Responses refresh after writes and when the tab regains focus, without optimistic publication or local persistence of private data. Production authentication, session revocation, provider rate limits and concurrency behavior need deployment-specific verification. Historical browser-local saves are not imported into Supabase or read by the application.
