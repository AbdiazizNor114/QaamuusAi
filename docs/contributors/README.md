# Contributor preparation pack

Prepared 25 October 2026. These are proposed pilot procedures, not claims of completed audio collection, trained models, funding or appointed staff. Existing production controls are described in [contributor launch](../contributor-launch.md).

QaamuusAI builds the datasets, models, evaluation tools and documentation that developers can use to create Somali language and speech applications. A consumer voice assistant is an example application, not the platform's whole purpose.

| Workstream | Deliverable | Completion condition |
|---|---|---|
| 1 | [Starter pack](start-here.md) | A newcomer can choose a role, set up and submit a reviewed first contribution |
| 2 | [Ten starter tasks](starter-tasks.md) | Each has scope, dependencies, an owner slot and acceptance criteria |
| 3 | [Text and speech standards](../data/speech-standard.md) | Records, permissions, review and release gates are defined |
| 4 | [Audio collection plan](../speech/collection-plan.md) and [consent draft](../speech/consent-draft.md) | Operational and participant-facing requirements are ready for review |
| 5 | [Model baseline and evaluation plan](../speech/model-baseline.md) | Candidates, licensing caveats, reproducible testing and decision gates are documented |
| 6 | [Three-month pilot budget](../funding/pilot-budget.md) | Assumptions, arithmetic, caps and funding priorities are explicit |

## Order and ownership

Start tasks T01–T04 together as people become available; one person can cover multiple responsibilities. Finish standards and consent review before collecting anyone's voice. Use only synthetic data for interface work. Baseline research can proceed before collection; real evaluation waits for authorized data and a frozen test split. Publication waits for independent review, permissions and an approved release manifest.

Owner appointments are **unassigned**. The founder must name a technical maintainer, language reviewer, data steward and budget owner before real collection. A contributor cannot independently approve their own work.

These documents do not run migrations, create GitHub issues, recruit people, send messages, purchase services, collect recordings or train models. Those activities require actual owners and the release gates described here.
