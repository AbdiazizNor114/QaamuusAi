# Access control

Browser-local roles are synthetic demo identities and protect no shared data. Never put real personal or sensitive unpublished data in this mode.

All shared tables enable RLS. Public clients can read published entries, articles and releases. Authenticated contributors can create drafts, read their own revisions and submit them through a function. Assigned reviewers and editors can read authorized proposals. Independent editors authorize publication and dispute resolution. Technical admins can read operational audit logs and profiles but cannot editorially transition proposals.

Published tables, review decisions, role assignments and audit logs have no direct client mutation policies. Workflow functions check identity, ownership, role, current status and nonempty rationale; review operations lock the revision row. Audit triggers preserve before/after proposal content. Exports omit unpublished revisions.

Use only the publishable key on server requests with user cookies. Keep service-role keys outside the application. API mutations require same-origin requests and schema-valid input. Profile/comment authors are taken from `getUser()`, never browser input. Default sign-in now uses email/password for existing verified accounts, sends no OTP email and grants no roles. Password setup requires a verified current session, matching confirmation and 12–128 characters; `updateUser()` changes only the authenticated account. Passwords never enter local storage, logs or test output for real users. Supabase's additional password-change protections remain enabled. Public registration/password recovery UI is pending; users signed out everywhere with no existing password must use authorized recovery after mail delivery is available. Legacy email callbacks/code verification remain for previously issued links. Next Proxy refreshes cookie sessions; protected handlers independently call `getUser()`.

Set `APP_ORIGIN` to the canonical HTTPS origin in production. Local request-origin handling accommodates Next's localhost normalization only for loopback hosts with the same port; unrelated hosts and origins remain rejected. With explicit user approval, the project's allowlist contains the exact local callback `http://127.0.0.1:3000/auth`. No wildcard redirects or weaker auth settings were added. Session responses are private/no-store. Shared profile/submission content is not persisted to local storage or replaced by demo identities. The user confirmed real sign-in and profile/draft persistence. Before wider shared use, finish revoked/refreshed session tests, concurrency, rate limiting, hosted RLS integration tests, backups and security review.

The approved third migration replaces direct scholar/article proposal inserts with validated, identity-derived RPCs. Scholar decisions reject self-approval. Role changes reject self-modification, serialize on an advisory transaction lock and audit the actor, target, role and rationale. Editors can grant/revoke reviewer/editor roles; technical admins can manage contributor/technical-admin roles without gaining editorial authority. The member directory returns display names, IDs and roles only to these authorities, never email addresses. No founding roles are seeded. A trusted audited bootstrap requires explicit approval identifying each account and permission.

Article proposals remain private to authors and authorized independent reviewers/editors. Publication requires recorded independent approval and a redistributable license; corrections create separate proposals and published versions. Dispute/resolution rationales remain in article decision history. Releases freeze server-selected published entries and attribution/license manifests; clients cannot overwrite release snapshots or published articles. The community API accepts only six allowlisted commands with Zod-validated payloads; PostgreSQL makes the final authority decision.

Local follow-on controls deny self-elevation and self-review, separate editorial and operational grants, enforce reviewer assignment, preserve article/release snapshots and validate saved state. Invalid saves are retained under a recovery key. Submitted text is escaped by React. Headers deny framing, object embedding, MIME sniffing and device permissions. The policy intentionally stops short of a nonce-based script CSP; add that with authenticated server integration. Browser-local permissions are demonstration behavior, not a security boundary.

All three migrations are tested with embedded PostgreSQL (PGlite), mocked Supabase `auth.uid()` and synthetic users. Ten scenarios cover dataset/article privacy, immutable snapshots, self-elevation/self-review denial, separated administrative powers, scholar decisions, publication, corrections, disputes, licensing and releases. The third migration was applied after approval of Supabase's policy-change warning; verification reports 14 RLS-enabled tables, seven new community functions and zero assigned roles. Hosted privileged RLS/session-revocation tests remain pending. Docker's daemon is unavailable for a separate local Supabase stack.
